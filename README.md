# auto-freelance

An automated pipeline for applying to freelance missions. It scans FreeWork,
Freelance-Informatique and Freelancermap (optionally Upwork and LinkedIn),
scores every posting against your own profile, writes a personalized,
non-generic cover letter for it with an LLM, and auto-submits the ones worth
sending on the three platforms that support it via Playwright — with every
other match prepared as a draft you send by hand.

Nothing about you ships in this repo. Your rate, skills, bio and past
projects live in a `config.yml` you generate locally (gitignored); the
committed `config.example.yml` only shows the shape of the data.

## Quick start

```bash
git clone <this-repo-url> auto-freelance
cd auto-freelance

python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
playwright install chromium

cp .env.example .env
# fill in OPENROUTER_API_KEY at minimum — required for drafting

python3 onboard.py
# ~5 minutes of prompts: name, rate, skills, platforms, bio -> writes config.yml

python3 pipeline.py --dry-run
# scans + scores only, zero side effects: no LLM calls, no writes, no submissions
```

Once `--dry-run` looks right, `python3 pipeline.py` runs the full pipeline.

## Session setup (needed for auto-submit)

FreeWork, Freelance-Informatique and Freelancermap require you to be logged
in to submit an application. That login is a one-time, manual step per
platform — a real browser window opens, you log in yourself, and the session
(cookies) is saved locally:

```bash
python -m job_scanner.submission.playwright --export freework
python -m job_scanner.submission.playwright --export freelance-informatique
python -m job_scanner.submission.playwright --export freelancermap
```

Sessions are saved to `~/.auto-freelance/sessions/<platform>.json` by
default (override with `AUTOFREELANCE_SESSION_DIR`) — outside the repo,
deliberately, since they're authentication secrets.

You do **not** need to do this before running the pipeline. Without an
exported session, submission for that platform degrades gracefully to
"manual apply": the offer is still scanned, scored and drafted, it's just not
auto-submitted. Nothing crashes.

Useful companion commands:

```bash
python -m job_scanner.submission.playwright --sessions   # session status per platform
python -m job_scanner.submission.playwright --list        # platforms with a form mapper
```

## Configuration

Everything personal lives in `config.yml` (gitignored — never commit it),
generated by `onboard.py` or hand-copied from `config.example.yml`, which is
the authoritative, commented reference for every field:

- `profile` — your name, company, contact links, default drafting language.
- `rates` — target/floor day rate and currency, used to filter and score.
- `skills` — weighted core skills and exclusions the scorer looks for.
- `conditions` — accepted remote setups and max mission duration.
- `platforms` — which boards to scan, plus per-platform overrides (e.g.
  Upwork in USD, its own quota).
- `search` — query keywords, minimum rate, pages per run.
- `scoring` — the global score threshold that gates drafting.
- `drafting` — your bio, anonymized past projects, and the OpenRouter model.
- `submission` — headless mode and the session directory.
- `notifications` — console output, optional Telegram.

Secrets (`OPENROUTER_API_KEY`, optional `TELEGRAM_BOT_TOKEN` /
`TELEGRAM_CHAT_ID`, and path overrides) live in `.env`, never in
`config.yml` — see `.env.example`.

## Commands

| Command | What it does |
|---|---|
| `python3 pipeline.py` | Full run: scan → score → draft → submit → persist → notify. |
| `python3 pipeline.py --dry-run` | Scan + score only. No LLM calls, no writes, no submissions. |
| `python3 pipeline.py --scan-only` | Scan + score + persist, no drafting or submission. |
| `python3 pipeline.py --submit-only` | Submit offers already drafted and stored in the local DB. |
| `python3 scan.py` | Stage 1 alone — fetch raw offers from enabled platforms. |
| `python3 score.py` | Stage 2 alone — score offers against your profile. |
| `python3 draft.py` | Stage 3 alone — write cover letters for offers above threshold. |
| `python3 submit.py` | Stage 4 alone — submit drafted offers via Playwright where possible. |
| `python -m job_scanner.submission.playwright --export <platform>` | One-time login/session export for auto-submit. |

The individual stage scripts are for debugging one step in isolation; day to
day, `pipeline.py` is what you run (by hand or on a schedule).

## Architecture

Offers flow through six stages, each owning one file/module, connected by a
single pivot format:

```
scan.py  ->  score.py  ->  draft.py  ->  submit.py  ->  repo.py  ->  notify.py
(job_scanner/sources)  (job_scanner/scoring)  (job_scanner/drafting)  (job_scanner/submission)
```

- **`job_scanner/models.py`** — `RawOffer`, the pivot model every platform
  translates into. Nothing downstream (scoring, drafting, submission,
  persistence) knows any other shape, which is what lets a new platform be
  added without touching the rest of the pipeline. The dedup key is
  `(source, external_id)`.
- **`job_scanner/sources/`** — one class per platform (`freework.py`,
  `freelance_informatique.py`, `freelancermap.py`, `linkedin.py`,
  `upwork.py`), each implementing `OfferSource.fetch(criteria)`. HTTP
  transport is injected as a `Fetcher` rather than imported directly, so
  parsing runs offline in tests against static HTML/JSON fixtures.
- **`job_scanner/scoring/`** — `OfferScorer` scores an offer 0-100 against a
  `CandidateProfile` built from your `config.yml`, with every point
  justified in `reasons`. `score.py` applies the per-platform threshold
  (`config.min_score_for(source)`).
- **`job_scanner/drafting/`** — `writer.py` calls an LLM (OpenRouter) with a
  system prompt from `prompts.py` to produce a short, situated cover letter
  in the platform's language, then validates it (length, banned brochure
  phrases, no leaked placeholders) before it's ever shown to you. `draft.py`
  orchestrates this across a batch, respecting per-platform score threshold
  and daily quota.
- **`job_scanner/submission/`** — `playwright.py` drives a real browser
  against an authenticated session (`sessions.py`), with a `FormMapper` per
  platform (`submission/forms/`, registered via `@register`) telling it
  where the apply button, message field and submit button live. It aborts
  cleanly on a login wall or CAPTCHA rather than guessing, and only reports
  success after finding real proof of it. `submit.py` decides, per offer,
  whether that's even attempted.
- **`repo.py`** — SQLite-backed persistence, deduplicated by `(source,
  external_id)`, tracking each offer's state through scanned → drafted →
  applied.
- **`notify.py`** — always prints a summary to the console; optionally also
  sends it to Telegram if configured.

## Adding a new platform

To **scan** a new platform, add a class to `job_scanner/sources/`
implementing `OfferSource` (see any existing source for the shape). To
support **auto-submit** on a platform, add a `FormMapper` to
`job_scanner/submission/forms/` and register it with `@register`. See
`CLAUDE.md` for the conventions both follow.

## Security

- Session files (`~/.auto-freelance/sessions/*.json`) are authentication
  secrets — never commit them, never move them into the repo.
- `config.yml` holds your real name, contact info and rate — gitignored,
  never commit it either. Only `config.example.yml` is versioned.
- `.env` holds API keys and tokens — gitignored.
